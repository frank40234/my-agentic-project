# EAM 公司資產管理系統 - L0 整體架構設計說明書

本文件定義「公司資產管理系統 (Enterprise Asset Management, EAM)」的整體架構、技術決策、模組設計與資料庫 Schema 規劃。

---

## 1. 系統概覽 (System Overview)

本系統使用 **.NET 10 (ASP.NET Core MVC) + SQL Server** 進行開發，提供資產大類、次類、品名、單位、資產基本資訊、資材室、儲位的維護與庫存查詢。

系統核心特色：
1. **單一登入 Cookie 驗證**：後端僅驗證由外部系統發送、夾帶工號與姓名 Claims 且時效為 5 分鐘的 Cookie。
2. **異動追蹤機制**：每張資料表皆包含建立人、建立時間、修改人、修改時間。
3. **邏輯刪除 (Soft Delete)**：不真正抹除資料庫資料，而是使用 `IsActive` 狀態欄位進行控制。
4. **物料編碼自動產生**：依照格式 `{大類代號}-{次類代號}-{品名代號}-{4位流水號}` 自動算號（如 `CH-L1-001-0001`）。

## 3. 技術棧摘要表格 (Tech Stack)

| 項目 | 技術決定 | 說明 |
| :--- | :--- | :--- |
| **主要框架** | ASP.NET Core 10.0 MVC | 提供高度整合的 MVC 設計模式與 Razor 視圖，適合以 HTML + JS 快速建置後台。 |
| **資料庫** | Microsoft SQL Server | 支援實體完整性、交易、Unique Constraint 以及高效的關聯查詢。 |
| **ORM** | Entity Framework Core 10.0 | 提供 Code First / Database First 開發模式與全域查詢過濾器（Global Query Filter）。 |
| **身分驗證** | Cookie Authentication | 自訂 Cookie 名稱，攔截未驗證請求導向至未授權提示頁。 |
| **前端設計** | Bootstrap 5 + Vanilla CSS | 確保現代、乾淨、直覺的資產管理網頁設計。 |
| **前端驗證** | jQuery + jQuery Validation | 確保使用者送出資料前欄位完整且符合格式（大類/次類/品名必填與代碼格式等）。 |

## 4. 關鍵架構決策與理由 (Key Architecture Decisions)

### 決策 1：全域 EF Core 軟刪除與追蹤過濾器
* **決策**：在 `DbContext.OnModelCreating` 中設定 `HasQueryFilter(e => e.IsActive)`，並在 `SaveChanges`/`SaveChangesAsync` 覆寫方法中自動填寫追蹤欄位（`CreatedBy`, `CreatedTime`, `UpdatedBy`, `UpdatedTime`）。
* **理由**：滿足「停用/啟用」邏輯刪除的需求，且不需要在程式碼中每次手動加 `where IsActive = true` 條件，防範因人為疏忽導致被停用資料曝露；且追蹤欄位自動從身分驗證中寫入，避免硬編碼。

### 決策 2：物料編碼產生併發衝突防範
* **決策**：在 `Assets` 資料表中針對 `MaterialCode` 與 `IsActive` 建立 `Unique Index`。在資產服務（`AssetService`）中，新增時包在資料庫 transaction 中，並藉由 `SELECT ... WITH (UPDLOCK, HOLDLOCK)` 或捕獲資料庫 UNIQUE 違反異常，以實作重試算號機制。
* **理由**：在多用戶環境下，同時新增同品名資產時極可能拿到相同流水號，此設計保證在資料庫端阻斷重複編碼，並在應用程式端自動重試生成。

### 決策 3：自訂 Cookie 單一登入與開發模擬器
* **決策**：自訂 Cookie 名稱為 `EAM_AUTH_COOKIE`。建立一個開發測試頁面 `/Auth/Simulator`，允許自由輸入工號與姓名，點擊後後端發出過期時間為 5 分鐘的 `EAM_AUTH_COOKIE`。
* **理由**：不修改現有已設計好的外部系統之餘，又能保證本機開發和展示時擁有高度可操作性。

## 5. 未來擴充點 (Extension Points)

1. **EXT-001 (編碼格式調整)**：
   物料編碼的組裝模組抽離至獨立的 `IMaterialCodeGenerator` 介面，如果日後大類或流水號長度要調整（例如從 4 碼變 5 碼），僅需建立一個新的實作類別並注入即可。
2. **EXT-002 (系統整合與 Webhook)**：
   在庫存數量發生異動時，可於 `InventoryRepository` 預留事件發送點，供日後與 ERP、採購或生產系統做 API Webhook 對接。
